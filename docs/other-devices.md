# Other Logitech devices

Logitech devices that aren't G devices (MX mice and keyboards, the MX Creative Keypad and others) get a screen for their settings, when they report at least one of the features below other than Easy-Switch. A device with none of them keeps the info page. Buttons, gestures, per-app settings, Flow, the keypad's key images and plugins stay in Logi Options+, and G-Lite never diverts a button (0x1B04): how the MX Mechanical Mini's bindings work, and what building them would take, is in [mx-key-bindings.md](mx-key-bindings.md).

Tried on a real MX Mechanical Mini over Bluetooth (2026-11-26, firmware 72.03): the backlight on and off, Automatic, Level, the Waves effect, F1–F12 as media keys, Disable Caps Lock and a fade delay, each seen on the keyboard, and Easy-Switch: the computers and names read, and switching to another computer. Battery saving wasn't changed. The rest is untested. The bytes come from Solaar's settings (facts only, it's GPL), OpenLogi's captures of a real MX Master 3S, MX Master 3, MX Anywhere 3S, MX Keys S and MX Mechanical Mini (`fixtures/devices/*/cases`), and the reports of an MX Creative Keypad and an MX Mechanical Mini.

## What the screen does

Each setting is sent live when it changes, on its own: one the device refuses is named in the status line, goes back to what the device has, isn't remembered and doesn't stop the others. Only the settings you change are kept (a preset counts for the settings it changes; Revert goes back to what was kept when the screen loaded), as `device.<device>` in `settings.txt`, and sent again each time the screen loads (at scan, and when the device wakes), so changes made with the device's keys or in Logi Options+ to other settings stay. With the backlight on Automatic, the level isn't sent again. The effect and F1–F12 are never kept: the keyboard keeps them itself and changes them with its own keys (Fn and the light key, Fn and Esc), which sending them again would undo. Presets are `profile.<device>.<name>`. Switching computers isn't kept or in presets.

The MX Mechanical Mini and the MX Keys S get a picture of their keys above the rows (`app/models/mx-mechanical-mini.json` and `mx-keys-s.json`, from photos of the US layouts), lit white while the backlight is on, as bright as the level, with the effect as the keyboard shows it (seen on the Mini; the speeds are guesses): Contrast dims the letters, digits and punctuation (not the key left of 1), F1–F4, F9–F12 and the arrows, Breathing fades all the keys, Waves sweep left to right, Reaction lights a key when it's pressed, Random lights keys at random. Going back to Static takes the Mini a few seconds, though G-Lite sends it at once. Its 0x4540 layout code (`0D` on a Swiss keyboard) picks the ISO picture, as on the G keyboards (`KeyLayout.Iso`).

| Box | Feature | Can be changed when |
|---|---|---|
| Brightness (Screens on a device that isn't a mouse or keyboard, like the keypad) | 0x8040 | the device has it |
| Pointer: Speed | 0x2201 | it lists more than one DPI |
| Scroll wheel: SmartShift, Switch to free spin at | 0x2111, else 0x2110 | the device has one |
| Scroll wheel: Invert scrolling | 0x2121 | fn 0 says the wheel can |
| Thumb wheel: Invert | 0x2150 | the device has it |
| Backlight: on, Automatic, Level, Effect, Fades after (hands away, hands near, plugged in), Battery saving | 0x1982 | Automatic needs both mode bits, Level needs manual mode and fn 2, Effect more effects than Static and None, Fades after all three delays reading above 0, Battery saving its supported bit. Once read, the rows the keyboard doesn't have are left out |
| Keys: F1–F12 as media keys, Disable Caps Lock, Num Lock, Scroll Lock, Insert, Windows key | 0x40A3, 0x4521 | the device has it; a key only when 0x4521 says it can be disabled |
| Easy-Switch | 0x1814, names from 0x1815 | more than one computer (else the box is hidden). With 0x1815, an unpaired computer can't be picked; without it, the question says how to come back from an empty one |

## The bytes

Function numbers, then parameters. Multi-byte values are big-endian unless noted.

- **0x8040 brightness**: fn 0 b0–1 the maximum (100 on the keypad), fn 1 b0–1 now, fn 2 `<hi> <lo>` sets it. Same as the G515.
- **0x2201 DPI**: fn 1 `00` lists the DPIs (a value with the top 3 bits set is a step: 200–8000 in steps of 50 on the MX Master 3S is `00C8 E032 1F40`), fn 2 `00` gives now at b1–2 and the default at b3–4 (used when now is 0), fn 3 `00 <hi> <lo>` sets it.
- **0x2110 SmartShift**: fn 0 gives b0 the mode (1 free spin, 2 ratchet), b1 the threshold, b2 the default. fn 1 `<mode> <threshold> <default>` sets them, and **0 in a byte leaves it**. G-Lite sends `00 <threshold> 00`, so the mode the wheel's button sets isn't touched.
- **0x2111 SmartShift, enhanced**: fn 0 b1 the default threshold, fn 1 the status like 0x2110 fn 0 (b2 the torque), fn 2 `00 <threshold> 00` sets the threshold.
  - The threshold is the wheel speed, in quarter turns a second, at which it switches to free spin. 255 means it never does: that's SmartShift off. G-Lite offers 1–50, like Solaar.
- **0x2121 scroll wheel**: fn 0 b1 bit 3 says it can invert. fn 1 b0: bit 0 diverts the wheel to software, bit 1 high resolution, bit 2 invert. fn 2 sets b0, with b1–2 sent back as read. G-Lite reads fn 1 just before writing and changes bit 2 only, so a diversion Logi Options+ set since isn't undone.
- **0x2150 thumb wheel**: fn 1 gives b0 diverted, b1 bit 0 inverted. fn 2 `<diverted> <inverted> 00` sets both, so G-Lite reads fn 1 just before and sends the diverted byte back as read. Its resolution can't be changed.
- **0x1982 backlight** (little-endian):
  - fn 0: b0 bit 0 on, b1 options (bit 2 battery saving, bits 3–4 the mode: 1 automatic, 2 set by the keys, 3 set by software), b2 what's supported (0x04 battery saving, 0x08 automatic, 0x20 set by software), b3–4 the effects, a bit per effect id (0 Static, 1 None, 2 Breathing, 3 Contrast, 4 Reaction, 5 Random, 6 Waves; OpenLogi's notes), b5 the level (only in mode 3; it reads 0 otherwise), b6–11 three fade delays, little-endian, in units of 5 s: hands away from the keys, hands near them, on external power (Solaar's names; the MX Keys S reads 30 s, 30 s and 300 s), b12–15 reserved (Logitech's spec x1982 v3). Mode 2 can't be set by software: G-Lite shows it as automatic and writes it back as automatic (mode 0, none selected, shows as not automatic). Outside mode 3 the slider shows the level lit now (fn 2 b1), and going to mode 3 without a level picked takes it, or the middle level when it reads 0 (faded), so the backlight isn't stored off. 0x2110's third byte, the threshold it goes back to at a reset, gets the threshold too; `FF` there (SmartShift off) isn't used as the slider's starting value.
  - fn 1 `<on> <options> <effect> <level> <durations>` writes the whole configuration, and the keyboard keeps it. `FF` as the effect leaves it; G-Lite sends the effect only when you pick one, and battery saving in the options' bit 2. Effects are offered in Logi Options+'s order (Static, Contrast, Breathing, Waves, Reaction, Random; not None). G-Lite reads fn 0 just before, sends the delays you picked (the others back as read; 5 s to 2 h, Solaar's note on the spec, the screen offers 5 s to 1 h plus the keyboard's own), sets the mode in bits 3–4, and sends the level only in mode 3 (else 0), like Solaar. With no level to send in mode 3, it sends fn 0's b5 back.
  - fn 2: b0 the number of levels, b1 the level lit right now (it fades when your hands leave), b2 the status, b3 the effect now (what the Effect row shows), b4–9 the factory fade delays. G-Lite takes the level from fn 0's b5, the stored setting, like Solaar.
  - The MX Keys S (v3) reports `01 1D 3D …` and 8 levels. On battery, it turns off and on at once, and lights when hands come near. Plugged in, the hand sensor seems off: turned on, it stays dark until a key is pressed (tried on a real one), so the screen says so under Backlight. OpenLogi names a temporary effect at fn 3 that might light it at once; its bytes aren't known, so it isn't used.
  - The MX Mechanical Mini on firmware 72.00 has v2 and reports `01 05 05 7F …`: b2 has neither mode bit, so it only gets on and off (and the effects, untried there). Its fn 2 reads `08 03 04` (8 levels, 3 lit). G-Lite writes `01 05 FF 00` then the delays and reserved bytes as read (all 0), and the keyboard takes it. Logi Options+ updated it to 72.03 (build 0014), which has v3: `01 1D 3D 7F 00 07 78 00 78 00 78 00` (manual, level 7, all seven effects, 10 min for each delay, as Options+ set them; Options+ shows one delay, 5 s to 30 min, and writes it to all three), and fn 2's factory delays are 30 s, 30 s and 300 s. Level 0 is off and 7 the brightest; the screen numbers them 0 to 7, as Logi Options+ does. Turning Automatic off stores the level the slider shows (the stored level reads 0 in automatic, and fn 2's is the room's). Plugged in, it's like the MX Keys S: turned on, it stays dark until a key is pressed (tried on a real one).
- **0x1814 Easy-Switch**: fn 0 gives b0 the number of computers and b1 the current one, counted from 0. fn 1 `<computer>` switches, and the device leaves without answering: G-Lite sends it with `Hidpp.SendWithoutReply`, which doesn't wait. It asks first.
- **0x40A3 F1–F12 for several computers** (OpenLogi's notes): fn 0 `<computer> 00 00` gives the computer, the state (1: F1–F12 are media keys, Fn gives F1–F12), the default and capabilities; `FF` is the computer in use. fn 1 `<computer> <state> 00` sets it, kept by the keyboard for that computer. The MX Mechanical Mini answers `FF 01 01 01`, and `FF 00 00` made F11 type F11 (tried on the keyboard). The MX Keys S takes `FF` but ignores it and reads 00 for it, whatever the computer has (2026-11-26); with the computer's Easy-Switch index (0x1814 fn 0 b1) it switches, and so does the Mini, so G-Lite uses the index and `FF` only on a device without 0x1814. Logi Options+ shows the state the other way round, as "Use F1, F2, etc. keys as standard function keys"; Fn and Esc switch it on the keyboard.
- **0x4521 disable keys** (OpenLogi's notes): fn 0 b0 the keys that can be disabled, fn 1 b0 those that are, fn 2 `<keys>` sets the whole set (bits: 1 Caps Lock, 2 Num Lock, 4 Scroll Lock, 8 Insert, 16 Windows). The MX Mechanical Mini answers `1D` (no Num Lock), and `01` disabled its Caps Lock (tried on the keyboard).
- **0x1815 hosts info**: fn 0 b0 bit 0 says names can be read. fn 1 `<computer>` gives b1 1 when paired and b4 the name's length. fn 3 `<computer> <offset>` gives up to 14 bytes of the name (UTF-8) from b2. The names stay out of reports: they often carry the owner's name.

## Not yet

- **Smooth scrolling** (0x2121 bit 1): set alone, Windows scrolls many times too fast (about 8 times on the G502 LIGHTSPEED; the MX Master 3S reports 15 steps a notch). Making it work hasn't been tried yet.
- SmartShift's torque (0x2111), Options+'s host names for computers it hasn't seen.
- **Sending again after a quick reconnect.** Remembered settings are sent when the screen is made: at the first scan, and after the device was seen asleep. A device that drops and comes back between two scans isn't sent them again, so one it forgets (like inverted scrolling) stays lost until G-Lite starts or the device sleeps. The mouse screen checks inverted scrolling every 5 s for this; this screen doesn't yet.
- **Bolt receivers** are read through register 0xB5 sub-register 0x5N (pairing), from Solaar, untested: no Bolt receiver has been tried with G-Lite.
