# G600

The G600 (USB C24A) doesn't speak HID++: Solaar leaves it out for that reason. Its settings are feature reports. G-Lite shows them on the mouse screen, read only. Nothing here has been tried on a real G600 yet.

Sources: libratbag's `driver-logitech-g600.c` and [tulth/g600prog](https://github.com/tulth/g600prog), both MIT, which agree byte for byte. [samyrataylor/g-manager](https://github.com/samyrataylor/g-manager) is a rewrite of g600prog. More in [research/more-references.md](research/more-references.md#g600-and-g300).

## Finding it

The HID++ scan doesn't find it, so `Devices.FindPlainHid` lists it (it's in `UnfoundModels`) and looks for its collection with usage page FF80, the one LGS uses. With that collection, `FoundDevice.IsG600` gives it the mouse screen with `G600Mouse`; without it, the info page, where a report can still be made. The Linux tools reach the reports on interface 1.

## Reports

- **F0**, 4 bytes: byte 1 bits 1–2 the DPI level, bits 4–7 the mode (0–2). Setting: `F0 40|(level << 1) 00 00` picks a level, `F0 80|(mode << 4) 00 00` a mode (libratbag; G-Lite doesn't send these yet).
- **F3, F4, F5**: one mode each, 154 bytes with the report id:

| Byte | Content |
|---|---|
| 0 | Report id |
| 1–3 | Colour |
| 4 | Effect: 0 solid (black is off), 1 breathe, 2 cycle |
| 5 | Effect duration, 0–15 s |
| 6–10 | Unknown (zero in g600prog's sample) |
| 11 | Report rate: 1000 / (1 + n) Hz |
| 12 | DPI shift's DPI, × 50 (0 off) |
| 13 | Default DPI level, 1–4 |
| 14–17 | Four DPI levels, × 50, 200–8200 (0 off) |
| 18–30 | Unknown |
| 31–90 | 20 buttons of 3 bytes: a code, then a modifier and a key used when the code is 0 |
| 91–93 | G-shift colour |
| 94–153 | The G-shift layer's 20 buttons |

- Button codes: 01–05 left, right, middle, back, forward, 06 and 07 buttons 6 and 7, 11 DPI up, 12 DPI down, 13 DPI cycle, 14 mode switch, 15 DPI shift, 16 default DPI, 17 G-shift. The modifier bits are the HID ones (01 left Ctrl to 80 right Win). `G600Mouse.Binding` shows each as the HID++ binding that does the same, so the Bindings view names it; mode switch shows as Cycle profile.
- Button order: G1–G3 the clicks, G4 and G5 the wheel tilts, G6 under the ring finger, G7 and G8 behind the wheel, G9–G20 the thumb keypad.

## Writing (not done)

g600prog writes a mode with SET_REPORT and waits 1.1 s after each one. The mouse keeps it; there's no erase or copy step like the HID++ profiles. On Windows that would be `HidD_SetFeature` with the whole 154-byte report. Before G-Lite writes: a report showing the reads work, then one change tried on the mouse, with the three reports kept as the backup.
