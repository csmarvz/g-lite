# G502 X LIGHTSPEED

What a G502 X LIGHTSPEED (wireless id 409F, USB C098, firmware MPM 30.00 build 0014) shows in its report, [reports/g502x-409f.txt](reports/g502x-409f.txt) (2026-11-19).

Status: it opens on the mouse screen like the G Pro Wireless. The button names below come from the factory bindings; pressing each button with the Buttons view open (the button spy) confirms them.

## Features

- 0x2201 v2 (DPI, 100 to 25600 in steps of 50), 0x8060 (report rate: 125, 250, 500 and 1000 Hz, `8B`), 0x8100 (onboard profiles), 0x8110 (button spy, 11 buttons), 0x2121 (scroll wheel), 0x1004 (battery, a percentage), and 0x1500, which G-Lite doesn't know.
- No 0x8070: the plain G502 X has no lights (the G502 X PLUS has). The screen shows "Lighting (not supported on this mouse)".
- Not 0x2202 or 0x8061, which the newer mice use ([newer-mice.md](newer-mice.md)).
- 0x2121: fn 0 byte 1 is `0C`, so the wheel can invert (bit 3). The ratchet reads `01`: the wheel's own switch picks ratchet or free spin.

## Onboard profiles

- 0x8100 info `01 03 01 05 02 0B 10 00 FF`: profile format 3, 5 profiles, 11 buttons, sectors of 255 bytes. Onboard mode, profile 0001 active. The layout is the G Pro Wireless's (`MouseProtocol`), so Save to mouse works as on it.
- The directory uses libratbag's entries: `00 01 01 00`, `00 02 01 00`, then 3 to 5 disabled (`00 03 00 00`…), then `FF FF 00 00`.
- Stages 800, 1200, 1600, 2400 and 3200, default stage 2 (1600). Report interval 1 ms.
- Bytes 0x1C–0x1F are `3C 00 2C 01`: 60 and 300, the same power-save and off times the G915 TKL keeps there. Not used by G-Lite on mice.
- Four LED records at 0xD0 (effects 0x0F and 0x10, intensity 100), though the mouse has no lights. G-Lite leaves them alone: it writes LED records only for the zones 0x8070 lists.
- The factory profiles (0101, 0102) end in `00 00`, with no CRC. Their specials end in `00 00` too, not `FF 00`.
- Sector 0100 holds firmware data (it contains `MPM30.00_B0014`), not a directory.

## Buttons

The factory bindings of profile 1, slot by slot, and the names G-Lite gives them (`Bindings.Names`):

| Slot | Binding | Name |
|---|---|---|
| 0 | Left click | Left button |
| 1 | Right click | Right button |
| 2 | Middle click | Wheel click |
| 3 | Back | Thumb, back (G4) |
| 4 | DPI shift (`90 07`) | Sniper (G6) |
| 5 | Forward | Thumb, front (G5) |
| 6 | Scroll left (`90 01`) | Wheel tilt left |
| 7 | Scroll right (`90 02`) | Wheel tilt right |
| 8 | Cycle profile (`90 0A`) | G9 |
| 9 | DPI up (`90 03`) | G8 |
| 10 | DPI down (`90 04`) | G7 |

Unlike the G502 LIGHTSPEED, Sniper comes before Forward, and the tilt and G buttons are in the other order.

Profile 2 (the same as its factory copy 0102) differs: slot 4 is G-shift (`90 0B`) instead of DPI shift, and slots 11 and 12, past the 11 buttons, hold Scroll down and Scroll up (`90 10`, `90 11`). Its G-shift layer from 0x60, slot by slot: Left, Right, Ctrl+T, Back, nothing, Forward, Ctrl+Shift+Tab, Ctrl+Tab, Ctrl+0, Ctrl+Z, Ctrl+X, then Volume down and Volume up in slots 11 and 12 (the wheel, while G-shift is held). G-Lite doesn't change that layer or the slots past the button count.

Confirmed on the mouse: the thumb buttons are G4 (back) and G5 (front), and the button spy matched the other names.

## Save to mouse

Tried once (2026-11-19), changing stage 2 from 1200 to 1250. The profile was written and read back the same (`MouseProtocol.WriteSector`), with stage 2 at 1250 and the default stage set to it. Then the reload, 0x8100 fn 3 `00 01`, answered error 02, which the G Pro Wireless doesn't do; `MouseProtocol.Store` ignores that error. When the screen read the mouse again, it showed no DPI stages and no Save to mouse: the profile part of the read had stopped early, which happens when one of its calls fails, but refused reads weren't logged then, so which one is unknown. They are now. The mouse went back to its owner before a report could show its state after the save.

To check, with the mouse again: a report right after a save (the mode, the active profile, sector 0001), and the log's refused reads. Whether fn 3 refuses the profile that is already active, or something else.
