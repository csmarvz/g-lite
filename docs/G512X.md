# G512 X 75

USB 046D:C35F, wired, 2025, 75% with 81 keys, two knobs above the navigation column (brightness and volume), a light bar along the front and TMR (magnetic) switches with adjustable actuation. It speaks HID++ 2.0 at index 0xFF.

G-Lite opens it on the keyboard screen with live lighting only, like the G915 (`Keyboards.G512X`). It has 0x8101 like the G515, so G-Lite claims the lighting the same way: 0x8101 fn 6 `05` (host mode), then 0x8071 fn 5. Its key map (`app/models/g512-x-75.json`) is built from G HUB's picture of the keyboard and the USB key codes: the column on the right is Del, Print Screen, PgUp and PgDn (a review said Ins, Del, PgUp, PgDn; G HUB shows DEL, PRNT, PG▲, PG▼), and the key left of F1 is Esc with a G on it. Under the keys, the light bar is drawn as 33 thin segments, 0x8081 ids 0xA0 to 0xC0 from left to right, so the Screen effect lights it by where each segment sits. A review gives the bar 33 zones on the G512 X 75 (39 on the G512 X 98), which matches the 33 lit ids 0xA0–0xC0. The order is a guess until the owner checks: no source maps these ids (OpenRGB, Solaar and Lghub were searched; Lghub lists the light-strip order on the G512 X, G713, G715 and G735 as unsolved). What the 13 ids 0xF2–0xFE light isn't known. G HUB shows the bar as its own zone ("Light Bar Zone"), next to "Keys Zone".

## What the report shows

- Features: 0x8071 v6 (RGB effects), 0x8081 (per-key lighting), 0x8040 (brightness), 0x8101 (onboard files), 0x4540 (layout, 01 on the reported keyboard), like the G515, plus features G-Lite doesn't know (0x00D0, 0x1B05, 0x1B08, 0x1B20, 0x8051, 0x4523, 0x00C3, 0x8061, 0x1602).
- 0x8071 has two clusters:
  - Cluster 0, the keys: 0x00 Off, 0x01 Static, 0x0A Breathe, 0x15 Cycle, 0x16 Wave, 0x17 Ripple, then 0x18 (unknown, parameters `00 0D 07 D0`). Effects 0 to 5 have the same parameter bytes as on the G515.
  - Cluster 1, probably the light bar: the same without Ripple. G-Lite sends Static there when Ripple is picked for both.
- With Lighting per zone on (G HUB's "Enable lighting per zone", "Keys Zone" and "Light Bar Zone"), G-Lite gives each cluster its own effect. Turning it off sends the keys' effect to both. The bar's light is kept after a `#` in `lighting.<device>` and in presets; without it, both get the same. The Screen effect covers both: whether the bar keeps its own 0x8071 effect while the keys get 0x8081 frames isn't tested.
- 0x8081 lit ids: 0x00–0x6F, 0xA0–0xC0 and 0xF2–0xFE. Neither group is a G HUB category with a known meaning (media 0x9B–0x9F, G keys from 0xB4, logo 0xD2), so both are probably what G HUB calls cosmetic lights (strips, glow).

## Why it doesn't save yet

Its onboard files aren't laid out like the G515's:

- The directory entries (0x0000, 0x0100) start `04 01 81 01 40 6F` and end `02`, where the G515's start `01 01 81 01 40 63` and end `FF`. Byte 9 is the profile's size: 0x6F (111 bytes) here, 0x63 (99) on the G515.
- The factory profile (0x0101) has one more byte at position 2 (`03`), so the idle times and the light records sit one byte later than on the G515: the records start at 31, the flags at 75.
- The user directory (0x0000) points to file 8 with the same CRC as the factory profile, so 0x0008 is a copy of it. The report asked for 99 bytes and got error 04; reports now read the size the directory gives.

A second report (G-Lite 0.0.19-alpha, below) read the whole factory profile: its 111 bytes are the G515's layout with the extra byte at 2, and the last 11 bytes are FF. The user profile 0x0008 gave no answer, though the directory lists it.

Before Save: the meaning of byte 2, and why 0x0008 doesn't answer.
