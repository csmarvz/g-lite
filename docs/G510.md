# G510 and G512 X 75 support

What it would take to support the G510 / G510s and the G512 X 75. Neither has been on this PC: nothing here is checked on a real keyboard yet.

## G510 / G510s

USB 046D:C22D, and C22E with its headset audio turned on. A 2010 keyboard. It doesn't speak HID++: G-Lite's HID++ scan skips it, and it goes through feature reports instead.

From the Linux driver `drivers/hid/hid-lg-g15.c` (GPL: only the facts are used here, no code), added in 2019 by Hans de Goede:

| Feature report | What |
|---|---|
| 0x04 | M1, M2, M3 and MR key LEDs, one bit each |
| 0x05 | Backlight colour, `05 R G B`. The driver reads it with GET_REPORT and sets it with SET_REPORT, 4 bytes. |

- The backlight is one colour for the whole keyboard. There's no hardware brightness: the driver scales R, G and B itself.
- The keyboard has its own light button that turns the backlight on and off.
- The LCD (160×43, mono) and the G-keys are separate. Leave them out.
- LGS lists the G510 on usage page 0xFF00 ([research/lgs-manifest-inventory.md](research/lgs-manifest-inventory.md)).

Not known yet:

- which collection takes reports 0x04 and 0x05
- whether the colour stays after a power cycle, or after unplugging
- whether it's kept per M1/M2/M3 bank, like LGS showed
- what the other feature reports do

### What G-Lite does now

`Devices.Scan` lists a G510 (any HID interface with PID C22D or C22E) as a `Found` with `PlainHid`, and skips it in the HID++ scan, so nothing is ever written to it. It gets the info page. Its report (`Report.Plain`) lists every HID collection of the keyboard: its usage, its report lengths, its feature report ids, and the value of each feature report read with `HidD_GetFeature`. That only reads. Collections Windows holds (the keyboard itself) are opened without access, so their layout is listed but reads may fail.

### Next

1. Get a report from a G510 owner. It shows which collection has report 0x05 and what it holds.
2. Set `05 R G B` with `HidD_SetFeature` on that collection, read it back, and check what happens after a power cycle.
3. A small screen: Off, a colour and brightness (scaled into the colour), like the G9x mouse screen. Presets come with `DevicePage`.

## G512 X 75

USB 046D:C35F, wired, 2025, with TMR (magnetic) switches and adjustable actuation. The G512 X 98 is its full-size sibling. It speaks HID++ 2.0 at index 0xFF: G-Lite already finds it and shows the info page (firmware "U1").

Its feature list isn't published anywhere. If its report shows 0x8071, 0x8081, 0x8040 and 0x8101 like the G515:

1. Open `Page515` from the features rather than the name ("G515" in `Found.IsG515`).
2. Add `app/models/g512-x-75.json`, with the 0x8081 id of each key from the report's lit ids, then checked by lighting keys one by one.
3. Check the screen over a direct USB link (index 0xFF, no receiver).
4. Compare its onboard files with the G515's before allowing Save. If they differ, start with live lighting only, like the G915.

Adjustable actuation is another feature with an unknown protocol. Leave it out.

Next: ask for its report (Report on its info page).
