# G300

The G300 and G300s (USB 046D:C246) don't speak HID++. Like the G600, their settings are feature reports on the vendor collection (usage page FF80, interface 1); the other two collections there refuse them. `G300Mouse` in `app/G300.cs`, picked by `FoundDevice.IsG300`.

Source: PeriHub (MIT), `docs/protocols/logitech-g300.md`, written from libratbag's `driver-logitech-g300.c` and ratslap's LGS captures, and checked on a real G300 on Windows: its three profiles read and compared with LGS (PeriHub issue #16), then saved, kept over a replug (#21). Not yet tried on a real G300 in G-Lite.

## Reports

| Id | Length | |
|---|---|---|
| F0 | 4 | Byte 1: the active profile in the high nibble (0–2), the DPI level in bits 1–2 (0–3) |
| F3, F4, F5 | 35 | Profiles 1 to 3 |

A profile report:

| Byte | |
|---|---|
| 0 | The report id |
| 1 | Light: bit 0 red, 1 green, 2 blue, each on or off (eight colours, 0 off). The other bits stay as read |
| 2 | Rate: 00 1000 Hz, 01 125, 02 250, 03 500 |
| 3–6 | The four DPI levels: DPI / 250 in the low bits, 0x80 on the default one (used after a profile change). All four are always there |
| 7 | DPI shift: DPI / 250 in the low nibble, 0x40 for none. Left as read |
| 8–34 | Nine buttons (left, right, wheel, then G4–G9), 3 bytes each: a function, then modifiers and a key |

Button functions: 00 a key (modifiers as in a USB report, then the usage; nothing when both are 0), 01–09 mouse buttons (01 left, 02 right, 03 middle, 04 back, 05 forward), 0A DPI up, 0B DPI down, 0C DPI cycle, 0D next profile, 0E DPI shift while held, 0F the default DPI level. `G300Mouse.Binding` shows each as the HID++ binding that does the same, and `Entry` turns a binding back; one the G300 can't do is refused on save.

## What G-Lite does

- Reads F0, then the active profile's report. The DPI stage shown is the profile's default level, the one Save writes; the level the DPI buttons left the mouse on isn't shown, so a save never moves the default by itself.
- Nothing is live (`MouseProtocol.State.SaveOnly`): the DPI level picked, its DPI, the rate, the colour and buttons 3 to 9 change when saved, and the status line says so. Unsaved changes stay when you switch to another device and back. Only Off and Static are offered, with no Brightness: the colour becomes the nearest of the eight, each channel on from half the brightest one.
- Save to mouse backs up the profile's report, reads F0 again and refuses if the mouse's profile button moved it to another profile since the screen read it, writes the whole report once (`SetFeature`), waits half a second and reads it back, up to three times, until it matches. The picked level becomes the default one. A level whose DPI wasn't changed keeps its byte as read, so one read outside 250 to 2500 doesn't block a save of something else. The left and right buttons keep what they have, as in LGS and PeriHub: a change to them is refused. Next profile (0x0D) shows as Next profile; Default DPI (0x0F) is kept but not offered in the Bindings list. Backups restore the same way. There's no factory profile.
- It never sets F0 (selecting a profile or level), F1 or F2; it only reads F0. So after a save the level in use stays as it was until the mouse changes profile or level (or a DPI button is pressed); whether a G300 applies a saved active profile at once isn't known.
- The demo has one (`FakeG300`), and the `g300` trace saves a profile.

## Not known

- Whether a change to the active profile applies at once.
- What F1, F2 and LGS's `F0 42 …` do (ratslap), and the high bits of the light and DPI bytes.
- PeriHub's tester's blue LED didn't light, in LGS too: a fault of that mouse.
